# Contributing

Contributions are welcome through pull requests on
<https://github.com/Barbhuiya12/TorchVIC>. Open an issue first for anything
larger than a small fix. Bug reports and feature requests also go to the
[issue tracker](https://github.com/Barbhuiya12/TorchVIC/issues)
([Contact](../about/contact.md)).

## Repository layout

```
torchvic/core/      the physics (snow, canopy, vegetation, soil, energy, ...)
torchvic/model/     the time loop (basin.simulate), state carry, routing
torchvic/io/        global parameter file, domain, params, forcing, history, state
torchvic/forcing/   MTCLIM and daily-forcing disaggregation
torchvic/parallel/  cell shards over N processes (--gpus), merge
torchvic/coupling/  runtime, connector API, ledger; coupling/connectors/
torchvic/flood/     GPU flood engine; reservoir/, groundwater/, quality/, crop/,
                    wateruse/, ensemble/ the models behind the connectors
tools/              input builders (flow directions, ERA5 forcing, ISC parameters)
verification/       the matrix against VIC 5.0.1 and 5.1.0
benchmarks/         timing drivers
tests/              the test suite
docs/               this documentation
```

## Conventions

* Every process function follows a VIC C function and cites the C file and
  lines it follows ([Process-to-C mapping](../mapping.md)). A change to the
  physics must keep the [verification](../verification.md) results.
* An option VIC accepts is either run as VIC runs it or refused by name; it is
  never silently ignored.
* New behaviour comes with a test ([Testing](testing.md)).
* TorchVIC is GPL-3.0-or-later. Code taken from or derived from another project
  needs a compatible license and an entry in `THIRD_PARTY_NOTICES.md`
  ([Code and license](../downloads/code.md)).

## Documentation

The documentation is MkDocs with the `readthedocs` theme, in `docs/` and
`mkdocs.yml`:

```bash
pip install -r docs/requirements.txt
mkdocs serve              # http://127.0.0.1:8000
mkdocs build --strict
```

Three pages are generated; edit the generator or its source, not the page. A
test fails when `docs/OPTIONS.md` and the code disagree.

| page | generated by |
|---|---|
| `docs/OPTIONS.md` | `python -m torchvic.io.options > docs/OPTIONS.md` |
| `docs/OUTPUT_VARIABLES.md` | `python tools/gen_output_variables.py > docs/OUTPUT_VARIABLES.md` |
| `docs/mapping.md` | `python docs/_gen/mapping.py > docs/mapping.md` (from the repository root) |
